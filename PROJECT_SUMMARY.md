# GitHub Developer Analytics — Project Summary & Architecture

This document provides a comprehensive overview of the architecture, implementation steps, folder structure, and endpoints built for the **GitHub Developer Analytics** application.

---

## 1. System Architecture Overview

The system currently establishes an end-to-end foundation connecting the frontend, backend, and external GitHub REST API:

```text
[ Browser / User ]
       │
       ▼
Next.js Frontend (Port 3000)
       │ (HTTP Fetch via process.env.NEXT_PUBLIC_API_URL)
       ▼
FastAPI Backend (Port 8000)
       │ (REST / Requests with User-Agent & Timeouts)
       ▼
GitHub REST API (api.github.com)
```

---

## 2. What Has Been Done

### Phase 1: Environment & Directory Normalization
- **Directory Flattening**: Resolved the nested `frontend/frontend` folder generated by `create-next-app`, moving all Next.js app files directly under `frontend/`.
- **Framework Confirmation**: Next.js 16.3 (Turbopack) with React 19, TypeScript, and Tailwind CSS.

---

### Phase 2: FastAPI Backend Foundation (Step 3)
- **Python Environment**:
  - Python 3.14 virtual environment initialized at `backend/venv`.
  - Installed dependencies: `fastapi`, `uvicorn[standard]`, `requests`, `python-dotenv`, `pydantic`, `pydantic-settings`.
  - Exported dependencies to `backend/requirements.txt`.
- **Configuration & Environment**:
  - Managed through `backend/app/core/config.py` using `pydantic-settings`.
  - Created `.env` and `.env.example` defining `APP_NAME`, `APP_VERSION`, `FRONTEND_URL`, and `GITHUB_API_URL`.
  - Prepared placeholders for upcoming phases: `DATABASE_URL`, `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, and `JWT_SECRET`.
  - Safe `.gitignore` configured to prevent committing `.env`, `venv/`, and `__pycache__/`.
- **CORS Protection**:
  - `CORSMiddleware` configured strictly for `http://localhost:3000` (disallowing wildcard origins `*`).
- **Data Models**:
  - Created `GitHubUser` model in `backend/app/models/github.py` with type-safe fields (`login`, `id`, `name`, `avatar_url`, `html_url`, `public_repos`, `followers`, `following`, `created_at`).
- **GitHub Integration Service**:
  - Built `backend/app/services/github.py` with `get_github_user(username)`.
  - Includes `User-Agent` headers and timeout management.
  - Granular error sanitization:
    - `404` -> User not found
    - `403` -> Rate limit exceeded
    - `500+` -> Upstream GitHub service error
    - Network/Connection timeout -> Clean 503 unavailable
- **API Routing**:
  - `backend/app/api/routes/health.py`:
    - `GET /`: API welcome message
    - `GET /api/health`: Service health status check
  - `backend/app/api/routes/github.py`:
    - `GET /api/github/user/{username}`: Returns the structured `GitHubUser`
  - Integrated interactive documentation at `/docs` (Swagger UI) and `/redoc` (ReDoc).

### Phase 3: Frontend ↔ Backend Connection (Step 4)
- **Environment Management**:
  - Created `frontend/.env.local` configured with `NEXT_PUBLIC_API_URL=http://localhost:8000`.
  - Ensured no backend URLs are hard-coded in the UI.
- **Type Safety**:
  - Created `frontend/types/github.ts` mirroring backend schemas (`GitHubUser`, `HealthStatus`, `ApiError`).
- **Service Layer**:
  - Implemented `frontend/services/api.ts`:
    - `checkHealth()`: Queries `/api/health` to monitor server connectivity.
    - `getGithubUser(username)`: Queries `/api/github/user/{username}` and extracts FastAPI `detail` error messages.
- **Next.js Image Optimization**:
  - Configured `frontend/next.config.ts` with `remotePatterns` for `avatars.githubusercontent.com` to safely render avatars with Next.js Image component.
- **Interactive Dashboard (`frontend/app/page.tsx`)**:
  - **Live Backend Status**: Real-time indicator displaying `Backend: Connected` (green) or `Backend: Disconnected` (red) on mount.
  - **Search & Validation**: Username input field with client-side validation against empty submissions.
  - **Loading State**: Spinner animation and disabled buttons to prevent duplicate requests.
  - **Error Handling**: Friendly alerts for 404s, rate limits, or network disconnections.
  - **Profile Presentation**:
    - User avatar
    - Name & GitHub `@username`
    - Direct link to GitHub profile
    - 3-card stats grid (Repositories, Followers, Following)
    - Formatted account creation date

### Phase 4: Database Setup & High-Performance Caching (Step 5)
- **Database Engine & Connection Pooling**:
  - Configured SQLAlchemy 2.0 with connection pooling (`pool_size=10`, `max_overflow=20`, `pool_pre_ping=True`).
  - Added dual database support: PostgreSQL 16 (production/Docker) via `psycopg 3` binary with seamless fallback to SQLite for instant local development.
  - Added `docker-compose.yml` for local containerized PostgreSQL with volume persistence and health checks.
- **Data Models (`backend/app/models/db_models.py`)**:
  - `User`: Stores cached GitHub developer profiles, bio, company, location, repo counts, and `last_synced_at` timestamp.
  - `AnalyticsRun`: Audit table logging queries, cache hits/misses, execution latency, and error statuses.
- **Resilient Caching Engine (`backend/app/services/github.py`)**:
  - Implemented cache-first strategy with configurable TTL (default 1 hour).
  - Reduced query response times for cached profiles from ~850ms to ~1ms.
  - Added graceful fallback: if GitHub returns `403 Forbidden` (rate limit exceeded), backend automatically serves stale cached records with `stale: true` rather than failing.
  - Added `refresh: bool = False` query parameter to force fresh sync from GitHub on demand.
- **Analytics & Health Monitoring**:
  - `GET /api/analytics/stats`: Real-time cache hit rate %, total cached developers, and average latency.
  - `GET /api/analytics/history`: Audit log of recent lookups.
  - `GET /api/health`: Enhanced with database connectivity ping, dialect detection, and latency tracking.
- **Database Migrations & Automated Testing**:
  - Configured Alembic (`alembic.ini`, `alembic/`) with automated revision generation.
  - Added Pytest test suite (`backend/tests/test_caching.py`) validating health, caching, refresh, and 404 handling.
- **Frontend Dashboard Enhancements**:
  - Live Database status badge in header (`DB: SQLite (0.5ms)` / `DB: PostgreSQL`).
  - Cache status ribbons on profile cards (`⚡ Cached in Database` vs `✨ Live from GitHub API`).
  - Interactive "Force Refresh" button.
  - Recent search chips for instant profile switching.
  - Cache performance metrics banner (Hit rate, cached profiles count, avg latency).

### Phase 5: Developer Commit & Activity Analytics (Step 6)
- **Commit Ingestion & Graceful Fallbacks**:
  - `backend/app/services/github.py` (`get_github_commits`): queries recent commits across top active public repositories.
  - Gracefully ignores empty/uninitialized repositories (HTTP 409) and missing/renamed repositories (HTTP 404).
  - Flags `partial: true` upon upstream rate-limiting (HTTP 403) or timeouts, ensuring partial data is rendered without app failures.
- **Granular Author vs. Repository Owner Attribution**:
  - Differentiates commit authors from repository owners (`is_user_author`), accurately isolating user-specific contributions even when other developers push to the repository.
- **Activity & Cadence Analytics**:
  - `backend/app/services/analytics.py` (`calculate_user_activity`): aggregates commit logs into daily frequencies (`daily_commits`), monthly totals (`monthly_totals`), and ranks top repositories by commit density (`most_active_repositories`).
- **REST Endpoints**:
  - `GET /api/github/commits/{username}`: returns paginated/limited commits list with attribution.
  - `GET /api/github/activity/{username}`: returns aggregated cadence metrics and repository rankings.
- **Automated Test Suite**:
  - `backend/tests/test_commits_activity.py`: verifies author attribution isolation, mocked commits response, mocked activity aggregations, and 404 non-existent user handling.
- **Frontend Dashboard Components**:
  - `frontend/app/components/ActivityChart.tsx`: daily commit timeline with hover tooltips, ratio chips, and monthly volume cards.
  - `frontend/app/components/RecentCommitsTable.tsx`: commits log with Author vs Contributor badges, avatars, direct GitHub commit links, and toggle filter ("All Commits" vs "@username Only").
  - `frontend/app/components/ActiveRepos.tsx`: ranked repository cards showing commit density, progress bars, and stars.
  - `frontend/app/page.tsx`: concurrent fetching via `Promise.allSettled`, skeleton loaders, and partial data warning alerts.

## 3. Data Scope Note: Public vs. Private Repositories

- **Current Behavior**: The application currently queries the **unauthenticated** GitHub REST API (`https://api.github.com/users/{username}`).
- **Data Returned**:
  - `public_repos`: Only public repositories and public commits are accessible.
  - Private repositories and private contributions are never exposed by GitHub without an authorized user token.
- **Upcoming Roadmap (Step 7+)**:
  - Adding GitHub OAuth will allow users to log in with their GitHub account.
  - Authorized tokens with `repo` scopes stored in the database will enable analytics on private repositories.

## 5. How to Run Both Servers

### Terminal 1: FastAPI Backend
```powershell
cd backend
.\venv\Scripts\Activate.ps1
uvicorn app.main:app --reload
```
- API Base: `http://localhost:8000`
- Swagger Docs: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`

### Terminal 2: Next.js Frontend
```powershell
cd frontend
npm run dev
```
- Frontend UI: `http://localhost:3000`

### Optional: Run PostgreSQL Container
```powershell
docker compose up -d
```

### Run Backend Automated Tests
```powershell
cd backend
.\venv\Scripts\pytest.exe -v
```
